# 轻相册 · PhotoOpt

*原图存 NAS，回忆随身带。*

轻相册是一款 Android 本地照片与视频压缩工具，适合已经使用 NAS 备份照片，又希望减少手机存储占用的人。

> 项目仍在开发完善中，功能和界面可能继续调整。本文以当前实现为准，截图后续补充。

## 为什么做这个应用

我使用 NAS 备份手机照片，但备份之后，原图仍然占着手机空间。我想要的是类似 iCloud「优化储存空间」的体验：把原件保存好，手机上只保留体积更小、方便随时翻看的版本。而我使用的 NAS 备份流程还缺少本地照片压缩这一步。

直接删除手机照片，日常翻看不方便；一直保留原图，手机空间又会越来越紧张。于是有了「轻相册」：为已经备份的照片生成更小的本地副本，沿用熟悉的相册分类，方便继续在系统相册中浏览。

它在手机本地完成压缩，无需登录，不申请网络权限。NAS 备份仍由你使用的 NAS App 负责；需要原图时，通过 NAS App 查看或下载。轻相册目前不提供自动备份、自动删除原件或按需取回原图的功能。

## 能做什么

- **批量压缩照片与视频**：选择一个或多个本地目录，也可以指定文件，扫描后逐项勾选。
- **按原目录整理小图**：默认生成同级的 `小图-原目录名`，保留子目录结构，前缀可自定义。
- **提供三档画质**：根据清晰度和空间需求选择，默认使用「更省空间」。
- **保留原件**：生成独立副本，不覆盖已有文件，也不会自动删除原照片或视频。
- **尽量保留拍摄信息**：处理拍摄时间、位置、方向等元数据，具体能力受文件格式限制。
- **查看处理结果**：记录成功、跳过、失败及体积变化，支持预览、查看历史任务和导出 JSON 报告。

只有压缩后确实变小的文件才会保存为副本。已经带有 PhotoOpt 处理标记的文件会跳过，避免重复压缩。

## 推荐实践：用相册管理 NAS 备份

这是一套我自己使用的整理方式：**先分类，再备份，再生成小图，最后清理手机原件。**

### 1. 在系统相册中创建备份相册

统一用 `备份-` 作为前缀，后面按用途命名，例如：

```text
备份-时间线
备份-卡证
备份-旅行
备份-家人
备份-xxx
```

「备份-时间线」可以存放日常记录，「备份-卡证」存放需要留存的卡片、证件照片，其他分类按自己的习惯补充即可。

这里的相册需要对应手机上的实际本地目录。如果系统相册创建的只是虚拟分类，需要先确认 NAS App 和轻相册能够选到对应文件目录。

### 2. 让 NAS App 只备份这些目录

在 NAS App 中，将需要备份的 `备份-xxx` 目录加入备份范围。

后续生成的 `小图-xxx` 目录不加入备份，避免把浏览副本再上传一遍。如果 NAS App 选择的是更上层的父目录，新生成的小图目录也可能被包含进去，需要检查实际备份范围。

### 3. 定期整理照片，等待备份完成

隔一段时间整理一次系统相册，把需要长期保存的照片移动到对应的 `备份-xxx` 相册，让 NAS App 完成备份。

生成小图、删除手机原件之前，先确认 NAS 中已有原件，并能够正常打开。若 NAS App 使用的是会同步删除的模式，需要先确认清理手机文件不会同时删除 NAS 中的原件。

### 4. 使用轻相册生成浏览副本

在轻相册中选择这些备份目录，扫描并生成小图。默认输出关系如下：

| 原相册目录 | 小图目录 |
| --- | --- |
| `备份-时间线` | `小图-备份-时间线` |
| `备份-卡证` | `小图-备份-卡证` |
| `备份-旅行` | `小图-备份-旅行` |

`小图-` 会直接加在原目录名前面，原有的 `备份-` 会保留。例如：

```text
Pictures/备份-时间线/旅行/IMG_001.jpg
→ Pictures/小图-备份-时间线/旅行/IMG_001.jpg
```

生成后，检查小图的清晰度和处理结果。失败或跳过的文件没有生成新副本，需要单独确认，不要把它们当作已经处理完成。

### 5. 清理原相册中的照片

确认 **NAS 原件已备份、小图可正常浏览** 后，再在系统相册中手动删除原目录里已经处理好的照片，保留小图用于日常查看。

**建议每个 `备份-xxx` 相册至少留一张图片。** 部分系统相册会在目录没有图片时隐藏相册，或清理空相册；留一张可以避免下次整理时还得重新创建。

以后重复「整理到备份相册 → NAS 备份 → 生成小图 → 清理原件」即可逐步养成习惯。

注意：生成小图时，原件和副本会同时存在，手机占用会暂时增加。应用显示的压缩减少量，是原件与小图的体积差；自行清理原件后，才会真正释放空间。系统相册的回收站也可能继续占用空间，具体以手机的清理机制为准。

## 如何使用

需要 **Android 12 及以上**。

1. **安装并授权**：安装 APK，按应用提示允许文件访问和照片位置信息访问。文件访问用于读取来源和创建同级小图目录，位置信息权限用于避免系统隐藏原照片的 GPS 信息。
2. **添加来源**：在「准备」页添加本地目录，或通过「指定文件」选择照片、视频。目录会递归扫描。
3. **选择画质**：选择压缩档位，确认目录前缀；通常保留默认的 `小图-` 即可。
4. **扫描文件**：进入「文件」页点击「扫描」，查看可处理文件及跳过原因。扫描不会生成副本或修改媒体文件。
5. **勾选并生成**：选择需要处理的文件，点击「生成小图」。视频默认不勾选，可开启「是否处理视频」或逐项选择。
6. **检查结果**：在「结果」页查看任务明细和预览。确认备份与小图后，再自行清理手机原件。

处理期间可以查看进度或停止任务，已完成的副本会保留。再次扫描时，已有同名输出会跳过，不会覆盖。

指定单个文件时，会根据该文件的父目录创建同级小图目录。请直接选择希望保留名称的相册目录作为来源。

## 画质选择

| 模式 | 照片处理 | 视频目标码率 |
| --- | --- | --- |
| 保留像素 | 不改分辨率，JPEG 质量 85 | 6 Mbps |
| 均衡 | 长边上限 2560 像素，JPEG 质量 82 | 4 Mbps |
| 更省空间（默认） | 长边上限 1920 像素，JPEG 质量 76 | 2 Mbps |

照片不会被放大。视频输出为 H.264 / AAC 的 MP4，实际体积与设备编码器、原文件内容有关。

第一次使用，可以先选少量照片比较效果，再决定批量使用哪一档。卡证、文字截图等内容尤其适合先放大检查细节。小图是有损压缩的浏览副本，需要打印、编辑或读取精细内容时，应使用 NAS 中的原件。

## 格式支持与限制

| 类型 | 当前行为 |
| --- | --- |
| JPEG | 压缩，并尽量保留原有元数据 |
| 静态 PNG / WebP | 转为 JPEG；含透明像素或动画时跳过 |
| MP4 / MOV / M4V | 支持符合条件的 SDR 视频转码 |
| 可识别的 Google JPEG Motion Photo | 压缩静态图片部分，原样保留内嵌视频 |
| vivo JPEG + MP4 实况配对 | 关联 ID 一致时按 B 方案成组压缩，保持原尺寸；未知配对仍跳过 |
| Apple Live Photo、无法可靠识别的其他实况格式 | 暂时跳过 |
| HDR / 多画面 JPEG | 仅处理主图，生成普通 JPEG；不保留 HDR 增益图、附加画面及相关私有信息 |
| HEIC / HEIF / AVIF / RAW、GIF、HDR 视频、特殊拍摄速率视频 | 当前跳过 |

180 KiB 以下的支持格式图片原样复制并写入标记；已有处理标记、目标重名等情况会跳过。扫描通过并不保证实际编码一定成功，完整原因可在「文件」页标题旁的问号及任务结果中查看。

应用会校验其支持的拍摄时间、位置、方向等信息，并尽量保留元数据，但无法保证所有厂商私有信息完整保留。新副本的媒体库添加时间、文件创建时间也不保证与原件相同。

## 常见问题

### 压缩后会自动删除原图吗？

不会。应用只生成独立副本，清理由你在确认备份与压缩效果后手动完成。

### 可以直接读取 NAS 上的照片吗？

当前处理手机本地目录中的文件，不直接连接 NAS，也不会修改 NAS App 的备份设置。

### 为什么部分照片没有生成小图？

可能是格式暂不支持、输出文件已存在、未勾选或处理失败。已经很小、压缩后没有变小的支持格式文件会原样复制并写入复制标记。请查看对应文件的处理记录。

### 再次处理同一个目录，会重复生成吗？

已有同名输出会跳过，带有 PhotoOpt 标记的文件也会跳过。应用不会覆盖已有输出；即使原件后来发生变化，同名输出存在时也不会自动更新。

### 删除任务记录会删除照片吗？

不会。删除记录只影响应用内的历史展示，原件和生成的副本都会保留。

```sh
./gradlew :app:assembleDebug
```

## 1.7：vivo 配对实况与原样复制

文件清单中同时包含 JPEG 与同名 MP4、且 vivo 私有配对 ID 一致时，按 B 方案成组选择处理。照片和视频都保持原尺寸；照片重新编码并保留原元数据、尾部、双图 MPF 增益图，修正偏移；视频 H.264 / AAC，保留 vivo UUID 数据并重新分配一致的配对 ID。普通视频开关不拆开实况组。未知配对继续跳过。厂商识别依赖私有格式，其他结构仍可能不支持。

两份输出均在临时文件中完成后才发布。私有提交日志记录临时文件的设备号和 inode；中断留下半组时，扫描识别为可重新处理，正式处理前仅清理仍与日志身份一致的半组输出。两份都已发布则保留；不会删除被其他软件替换的文件。不做压缩断点恢复。

小于 180 KiB 的支持格式图片，以及压缩后没有变小的媒体，改为原样复制并保留扩展名；复制并非字节完全相同，副本会加元数据标记，但不重新编码图像、音频、视频数据。JPEG 写 Comment，PNG 写 tEXt，WebP 写 EXIF UserComment，MP4/MOV/M4V 追加标准 ISO meta/mdta：`PhotoOpt:v1; action=copy; reason=...`。vivo 组整体没有变小时，整组采用此规则。记录注明原样复制，压缩减少计为 0。其他不支持、冲突、失败或未选择的文件仍可能没有输出，不能据此直接清空整个来源目录。


### 1.7.1：HDR / 多画面主图副本

非配对 HDR / 多画面 JPEG 可选中生成普通 sRGB JPEG 主图。清单、生成确认、处理记录和 EXIF UserComment 的 `primaryOnly=true` 均注明仅主图；副本不携带增益图、MPF、附加画面、原 XMP 和 MakerNote，只迁移拍摄时间、GPS、方向、相机/镜头、曝光等基础 EXIF 信息。原文件不变，已确认的 vivo 配对继续走保留增益图与配对的 B 方案。若结果不小于原文件，仍执行原样复制并写入 copy 标记，以实际记录为准。不可选择的文件（含已有同名输出）不再显示灰色复选框，保留详情预览。


### 实况只保留照片

文件页增加“实况只保留照片”开关，默认关闭。开启后，已识别的 vivo 配对实况与 Google 单文件实况只生成普通静态 JPEG，并保留基础时间/位置等信息、写入 `liveStillOnly=true; motionRemoved=true` 标记；vivo 配对视频明确记录为跳过，不单独输出。原始实况仍保留。未知、不支持的实况不会因开关而被强行转码。开启时显示“小图不能动了，但更省空间”的提示，生成前再次提示。切换无需重新扫描，可随时切回完整实况方案。若静态输出碰巧更大，仍保留静态结果并在记录中注明，不退回会动的原样副本。


### 隐藏已处理文件

文件页“隐藏已处理”默认开启，仅隐藏目标位置已有同名输出的文件；关闭即可查看。筛选数量随显示范围变化。无论开关是否开启，新的生成任务都不把这些文件计入总数、跳过数或报告明细；生成时才发现同名输出的文件仍计入总数，并在本次记录中注明跳过原因。其他未勾选、不支持或失败的项目仍保留记录。旧任务记录不追溯修改。实况配对中已有输出导致整组跳过时，整组都按已处理隐藏，并从新任务总数和记录排除。


### 1.7.6：统一选项与强制静态转换

文件页的四个独立选项统一为两行勾选框：是否处理视频、隐藏已处理、实况只保留照片、强制转普通图片。隐藏已处理默认开启，其余默认关闭。只有全选/清空是操作按钮，状态筛选继续用筛选标签。

“强制转普通图片”只开放扫描已能解码主图、但被判为未知实况/附加数据结构的 JPEG。开启后这些项目变为可选择，不自动勾选；无需重新扫描。关闭后恢复跳过并取消选择。输出不包含动态、未知附加内容或 HDR 增益图；基础时间/GPS/方向等尽量保留，写入 `forcedStatic=true; motionRemoved=true` 标记。不会放开损坏文件、不支持的其他格式、已存在输出或路径冲突。说明弹窗同步更新。


### 1.7.9：默认选项与分组筛选

是否处理视频、隐藏已处理、vivo 实况只保留照片、强制转普通图片，四项默认均选中，可逐项取消。文件筛选按展示组计算：只要组内有可处理照片或视频，就属于“可处理”；只有整组都不可处理才属于“已跳过”。仅照片模式下不输出配对视频，不会把仍可生成照片的整组放入已跳过。筛选数字按组，已选文件数仍按实际文件计算。


## 运维工具：检查文件处理标记

准备页右上角点击扳手图标进入“运维工具”，可选择本地目录递归检查，或指定图片/视频。工具直接读取文件元数据，不依赖任务记录或扫描缓存，不修改文件，也不会排除“小图-”目录。检查支持当前应用使用的 EXIF UserComment、JPEG Comment/APP 元数据、PNG 文本块以及 MP4 moov/meta/uuid 标记。可筛选有标记、未发现标记、读取失败、暂不支持，并点击文件查看路径、标记原文及处理方式。

“未发现标记”仅表示当前能读取的元数据中没有 PhotoOpt 标记，不证明文件从未处理过；其他软件可能删除了标记。读取失败和不支持的格式单独显示，不算作未处理。离开页面会停止未完成的检查。

### 含特殊拍摄速率元数据的照片

JPEG 提示“含特殊拍摄速率元数据”时，可在文件页开启“强制转普通图片”，再勾选该照片生成普通静态 JPEG。输出保留基础拍摄信息，移除特殊速率、动态及未知附加数据；原件保留。此选项不放行特殊速率视频或损坏的 JPEG。更新应用后需重新扫描，以刷新旧的检测结果。

普通视频携带 `com.android.capture.fps` 拍摄帧率标记时，应用会核对拍摄与播放帧率；两者一致（允许 5% 偏差）即可按普通视频压缩，无需开启“强制转普通图片”。帧率不一致、无法确认或含慢动作元数据时仍跳过。更新后需重新扫描。
