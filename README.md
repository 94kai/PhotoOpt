# 轻相册 · PhotoOpt

*原图存 NAS，回忆随身带。*

轻相册是一款 Android 本地照片与视频压缩工具，适合已经使用 NAS 备份照片，又希望减少手机存储占用的人。它为原件生成独立的小图副本，沿用原来的目录分类，方便继续在系统相册中浏览。

**Android 12+ · 本地处理 · 无需登录 · 不申请网络权限 · 原件保留**

> 项目仍在完善中。当前默认开启实况转静态和强制转普通图片；如果希望小图仍能播放实况，请先取消对应选项。生成副本不会自动释放空间，需要确认备份和输出结果后自行清理原件。

## 为什么做这个应用

我使用 NAS 备份手机照片，但备份之后，原图仍然占着手机空间。我想要的是类似 iCloud「优化储存空间」的体验：把原件保存好，手机上只保留体积更小、方便随时翻看的版本。而我使用的 NAS 备份流程还缺少本地照片压缩这一步。

直接删除手机照片，日常翻看不方便；一直保留原图，手机空间又会越来越紧张。于是有了「轻相册」：为已经备份的照片生成更小的本地副本，保留熟悉的相册分类。

NAS 备份仍由你使用的 NAS App 负责；需要原图时，通过 NAS App 查看或下载。轻相册不提供自动备份、自动删除原件或按需取回原图的功能。

## 功能

- **多个来源**：选择多个本地目录递归扫描，或指定图片、视频，再逐项勾选。
- **独立输出目录**：默认生成同级的 `小图-原目录名`，保留子目录结构，支持自定义前缀。
- **三档画质**：保留像素、均衡、更省空间，默认使用更省空间。
- **实况与主图处理**：支持部分 vivo 配对实况、Google 单文件实况；也可只保留静态照片，或从部分未知结构中提取普通主图。
- **原样复制补齐**：支持格式的小文件、压缩后没有变小的文件，会复制到输出目录并写入处理标记。
- **原件保护**：不覆盖已有输出，不自动删除原件；尽量保留拍摄时间、位置、方向等信息。
- **任务历史**：按次记录成功、跳过、失败、未处理及体积变化，可预览、导出 JSON、删除记录。
- **标记检查**：运维工具可直接检查目录、图片或视频内的 PhotoOpt 标记。

## 快速使用

1. **安装与授权**：安装 APK，允许本地文件访问和照片位置信息访问。
2. **添加来源**：在「准备」页添加本地目录，或通过「指定文件」选择图片、视频。
3. **选择画质与前缀**：默认「更省空间」，输出目录前缀默认 `小图-`。
4. **扫描**：进入「文件」页点击「扫描」。扫描不会编码或修改媒体文件，相当于只读演练；内部检测缓存会更新。
5. **确认选项、勾选文件**：检查可处理项、跳过原因和目标路径，再点击「生成小图」。
6. **检查结果**：查看任务记录和副本效果，确认 NAS 已保存原件后，再自行清理手机原件。

### 文件页四个选项

**四项默认全部勾选**，可以按需要取消。

| 选项 | 勾选后的行为 |
| --- | --- |
| 是否处理视频 | 自动勾选可处理的普通视频；仍可逐项调整，不改变扫描范围 |
| 隐藏已处理 | 隐藏已有同名输出的文件，以及因配对文件已有输出而整组跳过的项目 |
| vivo实况图只保留照片 | 已识别的 vivo 配对、Google 单文件实况只生成静态照片，小图不能动，原始实况保留 |
| 强制转普通图片 | 允许选择主图可读取、但动态/附加结构或部分拍摄元数据不受支持的 JPEG，仅生成普通静态主图 |

希望保留已支持实况的动态时，取消「vivo实况图只保留照片」。对于原本不支持的结构，「强制转普通图片」只能提取静态主图，不能恢复或保留动态。

手动开启强制转换后，相关文件变为可选择，需要自行勾选；重新扫描则会按当前选项选择可处理项。关闭选项会恢复对应的处理限制。

同目录同名照片、视频成组展示。只要组内还有可处理文件，就属于「可处理」；整组都不可处理才属于「已跳过」。筛选数量按组计算，已选文件数按实际文件计算。

## 输出到哪里

前缀直接加在来源目录名前面，原目录名和子目录结构保留：

```text
Pictures/备份-时间线/旅行/IMG_001.jpg
→ Pictures/小图-备份-时间线/旅行/IMG_001.jpg
```

单独选文件时，按它所在的父目录生成同级输出目录。不同目录的文件分别输出：

```text
Pictures/旅行/a.jpg  → Pictures/小图-旅行/a.jpg
DCIM/Camera/b.jpg    → DCIM/小图-Camera/b.jpg
```

如果指定文件同时位于已添加的来源目录内，则沿用该来源目录的规则。重叠来源会去重。

正常转码时，PNG/WebP 转为 `.jpg`，视频转为 `.mp4`；原样复制保留原扩展名。发生目标重名时跳过，不覆盖已有文件。切换画质或处理选项也不会自动替换旧副本；需要比较不同方案时，可使用不同目录前缀。

## 推荐实践：用相册管理 NAS 备份

这是我自己使用的整理方式：**先分类，再备份，再生成小图，最后清理手机原件。**

### 1. 创建备份相册

在系统相册中按用途创建 `备份-时间线`、`备份-卡证`、`备份-旅行`、`备份-家人` 等相册。

这里的相册需要对应手机上的实际目录。如果只是虚拟分类，要先确认 NAS App 和轻相册能够选到对应文件目录。

### 2. 让 NAS App 只备份原件目录

将需要备份的 `备份-xxx` 目录加入 NAS App 的备份范围，后续生成的 `小图-备份-xxx` 目录不要加入。

**如果备份范围选的是更上层的父目录，新生成的小图目录也可能被包含进去。** 轻相册不会修改飞牛或其他 NAS App 的设置，也不依赖保留文件时间来绕过增量备份。

### 3. 整理照片，等待备份完成

定期把需要长期保留的照片整理到对应目录。生成副本、清理手机原件前，确认 NAS 中已有原件并能正常打开。

如果 NAS App 使用同步删除模式，还要确认清理手机文件不会同时删除 NAS 中的原件。

### 4. 生成并检查小图

选择备份目录，扫描并生成副本。检查画质、时间线、位置及实况播放效果，查看任务中的失败和跳过原因。

小文件或压缩后未变小的文件会原样复制，但**不支持、冲突、失败和未选择的文件仍可能没有副本**。不要把整个原目录都当成已经处理完成。

### 5. 自行清理已经确认的原件

确认 NAS 备份和副本后，再在系统相册中清理相应原件。如果系统相册会隐藏空目录，可以留一张照片保留相册入口。

生成期间原件和副本同时存在，手机占用会暂时增加。清理原件后才能释放空间；系统相册的回收站也可能继续占用空间。

## 画质与空间统计

| 模式 | 普通照片 | 普通视频 |
| --- | --- | --- |
| 保留像素 | 保持分辨率，JPEG 质量 85 | 保持显示尺寸，目标 6 Mbps |
| 均衡 | 长边上限 2560，JPEG 质量 82 | 长边上限 1920，目标 4 Mbps |
| 更省空间（默认） | 长边上限 1920，JPEG 质量 76 | 长边上限 1280，目标 2 Mbps |

照片不会被放大，视频采用 H.264 / AAC。实际质量、码率和体积取决于内容及设备编码器。保留完整 vivo 实况时，照片与视频都保持原尺寸，以维持已支持的私有数据关系。

小于 **180 KiB（184,320 字节）** 的支持格式图片，以及编码后不比原件小的文件，会改为原样复制并增加元数据标记。这里的“原样”指不重新编码画面、音频或视频；由于增加标记，文件字节并非完全一致，体积可能略有增加。

如果明确选择只保留静态照片，即使静态结果偶尔没有变小，也不会退回会动的原文件，记录会注明结果。

「累计压缩减少」统计保留任务记录中的体积差，原样复制的减少量记为 0。它**不是当前已释放的存储空间**，也不是手机剩余空间；删除任务记录会相应改变累计值。

## 格式支持与限制

| 类型 | 当前行为 |
| --- | --- |
| 普通 JPEG | 压缩，尽量保留 EXIF、XMP、ICC、IPTC 等信息 |
| 静态 PNG / WebP | 转为 JPEG；实际处理发现透明像素或动画时跳过；小文件原样复制 |
| MP4 / MOV / M4V | 支持符合条件、设备可解码的 SDR 视频转码 |
| Google JPEG Motion Photo | 支持结构已识别的文件；默认转静态，取消仅照片选项后保留内嵌视频 |
| vivo JPEG + 同名 MP4 | 核对私有配对 ID；默认只生成照片，取消仅照片选项后成组压缩并保留已支持的关联数据 |
| HDR / 多画面 JPEG | 仅生成普通 sRGB 主图，不保留 HDR 增益图和其他附加画面；完整 vivo 配对分支单独处理已支持结构 |
| 未支持的实况/附加结构 JPEG | 主图可读取时，可通过强制转换生成普通主图；动态、未知附加数据不保留 |
| Apple Live Photo、其他未确认的同名配对 | 暂时跳过，不凭文件名强行当作已支持实况 |
| HEIC / HEIF / AVIF / RAW、GIF、HDR 视频、特殊速率视频 | 暂不转码或按检测结果跳过；未列出的格式不保证会被目录扫描收集 |

主图提取保留基础拍摄时间、GPS、方向、相机/镜头和曝光等 EXIF 信息，不保留描述已移除画面的 XMP、MakerNote 等私有结构，并写入相应标记。原件不变。厂商实况使用私有格式，目前只验证过部分 vivo 样本，不保证所有机型、系统版本和相册都兼容。

拍摄与文件时间也有区别：应用尽量恢复源文件的修改时间，但新文件的创建时间、媒体库添加时间不保证一致。

### 特殊拍摄速率

JPEG 中发现不支持的拍摄速率元数据时，可通过「强制转普通图片」提取静态主图。

视频里的 `slowMotion=none` 等明确关闭值不会被当成慢动作。带 `com.android.capture.fps` 的普通视频，会核对拍摄与播放帧率，两者一致（允许 5% 偏差）时可以转码。帧率不一致、无法确认或含有效慢动作元数据时仍跳过；强制图片转换选项不会放行这些视频。

扫描通过不保证最终成功。空间不足、解码/编码失败、原文件变化或元数据校验失败，都会在结果中说明。

## 任务记录与中断

- 每次生成独立保存记录，包含时间、文件路径、结果、大小及原因。
- 点开文件明细可以预览照片、播放视频。优先读取原路径，原件不可访问时尝试记录中的输出路径。
- 扫描时已确认存在同名输出的文件，以及因配对已有输出而整组跳过的项目，不计入新任务总数和记录。生成途中才发现同名输出时仍记录为跳过。
- 其他未勾选、失败、不支持和未处理项目会保留记录。旧任务不会因新规则而追溯改写。
- 导出 JSON 便于排查；删除记录不会删除原件或副本。

生成任务有前台通知，切换 Tab 仍能看到进度。停止或中断后不做压缩断点续传，重新扫描即可重新处理剩余文件。正式处理前会清理本应用的临时残留；完整 vivo 配对使用成组提交记录处理半组输出。

已有同名输出按存在直接跳过，不额外校验其完整性或重新压缩。因此被其他软件事后替换或改坏的输出，也不会被自动覆盖。

扫描最多 4 路并行，并缓存未变化文件的检测结果；源路径、大小或修改时间变化时重新检测。生成目前仍逐文件或逐组串行执行。

## 运维工具与处理标记

准备页右上角点击**扳手图标**，可选择目录递归检查，也可以指定图片或视频。工具直接读文件元数据，不依赖历史记录和扫描缓存，不修改文件，也不会排除小图目录。

| 标记 | 含义 |
| --- | --- |
| `PhotoOpt:v1` | 应用处理标记的版本；不是 App 版本号 |
| `profile=...` | 使用的压缩档位 |
| `action=copy` | 原样复制，`reason` 说明复制原因 |
| `primaryOnly=true` | 只保留主图 |
| `motionRemoved=true` | 动态内容已移除 |
| `forcedStatic=true` | 对未支持结构执行了强制静态转换 |

根据输出格式，标记可能位于 EXIF UserComment、JPEG Comment、PNG 文本块或 MP4 元数据中。并非每个文件都有表内所有字段；工具会显示找到的原文及位置，兼容本项目实验副本使用的标记。

检查结果区分「有标记」「未发现标记」「读取失败」「暂不支持」。“未发现标记”不能证明文件从未处理过，其他软件可能删除了元数据。

## 权限与隐私

- **所有文件访问**：读取本地来源，并在旁边创建输出目录；不支持直接处理云文件提供商或 NAS 远程文件。
- **照片位置信息访问**：避免系统隐藏源文件 GPS 信息，便于迁移到副本。
- **通知、前台服务和唤醒锁**：展示、维持生成任务；系统仍可能中断后台工作。

应用不申请网络权限，无登录和自动上传功能。任务记录保存在应用私有目录；导出的报告包含源路径、文件名等信息，提交问题反馈前可先脱敏。

## 本地构建与发布

开发环境：**JDK 17、Android SDK Platform 35**。项目包含 Gradle Wrapper（8.11.1），无需另行安装 Gradle。

1. 用 Android Studio 打开项目，安装所需 SDK，选择 JDK 17 作为 Gradle JDK。
2. 通过 Android Studio 配置 SDK 路径，或在本地 `local.properties` 中设置 `sdk.dir`；该文件已被 Git 忽略。
3. 在项目根目录执行：

```sh
./gradlew :app:assembleDebug :app:lintDebug
```

Windows 使用 `gradlew.bat`。调试 APK 输出到：

```text
app/build/outputs/apk/debug/app-debug.apk
```

可通过 USB 安装到手机：

```sh
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

技术栈：Kotlin 2.0.21、Jetpack Compose / Material 3、ExifInterface 1.4.1、Media3 1.5.1；应用 ID 为 `com.xk.photoopt`，最低 API 31，compile/target API 35。

**正式发布**时，请在 Android Studio 中生成签名 APK，并妥善保存自己的签名密钥。当前工程没有配置 release 签名；调试 APK 与使用不同证书签名的正式 APK 不能直接覆盖更新。不要把签名文件、密码或本机 SDK 路径提交到仓库。APK 可作为 GitHub Release 附件发布，源码仓库无需包含构建产物。
